## 2026-09-02 - Destructive Action Protection and Focus Styling
**Learning:** In a real-time system (like Firestore), users expect immediate UI feedback, but failing to provide a native confirmation dialog for destructive actions (like delete) causes frustrating accidental data loss, particularly because this app lacks an undo feature. Additionally, when using Tailwind utility classes on interactive elements, relying only on hover states (`hover:bg-red-200`) makes the action completely invisible to keyboard-only users who navigate via the Tab key.
**Action:** Always place `window.confirm()` prompts before authentication checks on destructive actions (to allow local testability without auth), and mandate the addition of `focus-visible:ring-2 focus-visible:ring-offset-1` utilities alongside hover classes on all interactive components to ensure keyboard accessibility.
