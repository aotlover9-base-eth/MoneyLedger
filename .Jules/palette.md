## 2024-11-23 - Placement of UI Confirmation Dialogs for Destructive Actions
**Learning:** When adding native UI confirmation dialogs (like `window.confirm()`) for destructive actions (e.g., deleting an entry) in components that rely on backend state (like Firebase auth), the placement of the dialog prompt is critical for local testing. If placed *after* an early return for an unauthenticated state, the prompt will never trigger during unauthenticated local testing with mock data.
**Action:** Always place confirmation dialog prompts for destructive actions *before* any early returns that check for authentication or backend initialization (e.g., `if (!userId || !db) return;`). This ensures the UX interaction can be fully tested locally even when the backend is unavailable or uninitialized.
