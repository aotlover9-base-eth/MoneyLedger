## 2026-07-14 - Button Accessibility and Disabled State UX
**Learning:** For repeated actions in lists (like delete buttons), screen reader users need specific item context in the `aria-label` (e.g., "Delete Savings entry" instead of just "Delete Entry") to avoid ambiguity. Additionally, users often struggle to understand why a primary action like "Add Entry" is disabled; providing visual feedback (`cursor-not-allowed`) combined with a contextual tooltip (`title`) explaining missing fields significantly improves disabled state clarity.
**Action:** Always inject specific item context into `aria-label`s for repeated list actions. For disabled primary buttons, always pair a `not-allowed` cursor with a `title` (or tooltip component) explaining the exact requirements to enable the action.
