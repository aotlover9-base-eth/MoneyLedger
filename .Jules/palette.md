## 2024-08-18 - Local Testing of Destructive Actions with Native Dialogs
**Learning:** When using `window.confirm()` or other native dialogs for destructive actions (like deleting items) in an application with authentication, placing the confirmation prompt *before* any early returns that check for authentication state (e.g., `if (!userId || !db) return;`) is crucial. This structure allows the confirmation dialog to be triggered and tested locally using mock data, even when Firebase authentication fails or is uninitialized.
**Action:** Always insert user confirmation prompts as the first statement in a destructive action handler, before any environment or authentication checks, to ensure local testability and consistent UX feedback regardless of the app's connection state.
